# Z Note Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A minimal Markdown note-taking web app (create/edit/delete/search/pin, live preview, autosave, light/dark) that deploys to Vercel in one click with a Neon Postgres database.

**Architecture:** Next.js App Router with server components reading Postgres directly and server actions for every write — no API routes. A note is just Markdown `content`; its title is derived from the first line. The schema is created lazily (idempotent `CREATE TABLE IF NOT EXISTS`) on the first query of each server instance, so a fresh Vercel + Neon deploy needs no manual setup step.

**Tech Stack:** Next.js (latest, App Router) · React 19 · TypeScript (strict) · Tailwind CSS v4 + `@tailwindcss/typography` · shadcn/ui (base color `neutral`) · `@neondatabase/serverless` · `next-themes` · `react-markdown` + `remark-gfm` · `lucide-react` · Vitest + `@electric-sql/pglite` (tests only)

**Spec:** `docs/superpowers/specs/z-note-spec.md`

## Global Constraints

- App name in all copy and metadata: `Z Note`.
- Strict graphite gray and white palette: every color token in `app/globals.css` is achromatic (oklch chroma `0`), including `--destructive`, `--chart-*` and `--sidebar-*`. No yellow, no accent colors.
- No shadows and no decorative elements: no `shadow-*` class anywhere in `app/` or `components/` (including `components/ui/`).
- Brand mark: the hand-drawn graphite `Z` icon (`public/icon-192.png`), rendered with `dark:invert` in dark mode.
- No authentication.
- Database env var: `DATABASE_URL` only (the Neon Vercel integration sets it). Missing at runtime → error message `DATABASE_URL is not set. See README.`; missing at build → build still succeeds.
- Markdown preview never renders raw HTML (no `rehype-raw`).
- Package manager: npm. Node ≥ 20.9.
- Runtime dependencies are limited to what create-next-app and shadcn install plus: `@neondatabase/serverless`, `next-themes`, `react-markdown`, `remark-gfm`, `@tailwindcss/typography`. Dev additions: `vitest`, `@electric-sql/pglite`.
- Next.js 15+ semantics: `params` and `searchParams` are Promises — `await` them.

## Review Focus

1. **Leaving a note within the autosave delay** (clicking another note, closing the tab) → the last edit is saved, or the browser warns before unload. Pinned by the `flush` tests in Task 3; `beforeunload` checked manually in Task 6.
2. **Slow or failing network during autosave** → saves never overlap, the newest text always wins, and a failure shows `Save failed` and is retried on the next edit. Pinned by Task 3 tests.
3. **Search for `%`, `_` or `\`** → matched literally, not as LIKE wildcards. Pinned by Task 2 (`escapeLike`) and Task 4 (`listNotes`) tests.
4. **Hand-typed or stale note URL** (`/notes/abc`, a deleted id) → 404 page, not a 500. Pinned by Task 4 `getNote` tests.
5. **Empty, whitespace-only or heading-marker-only note** → shows `Untitled` in the sidebar, never a blank row. Pinned by Task 2 `noteTitle` tests.

### Task 3: Autosaver

**Files:**
- Create: `lib/autosave.ts`
- Test: `lib/autosave.test.ts`

**Interfaces:**
- Produces:
  ```ts
  export type SaveStatus = "saved" | "pending" | "saving" | "error";
  export function createAutosaver<T>(opts: {
    save: (value: T) => Promise<void>;
    delay: number;
    onStatus: (s: SaveStatus) => void;
  }): { update(value: T): void; flush(): Promise<void>; dispose(): void };
  ```

Rules: `update` stores the latest value, emits `pending`, restarts the timer. When the timer fires (or `flush` is called) and a save is in flight, wait for it; otherwise emit `saving` and save the latest value. After success, if a newer value arrived, save again; else emit `saved`. On failure emit `error`, keep the value dirty, and do not retry automatically. The next `update` or `flush` retries. `flush` clears the timer and resolves once nothing is dirty or in flight (no-op when clean). `dispose` clears the timer.

- [ ] **Step 1: Write the failing tests**

```ts
import { it, expect, vi, beforeEach } from "vitest";
import { createAutosaver, type SaveStatus } from "./autosave";

beforeEach(() => vi.useFakeTimers());

function setup(save: (v: string) => Promise<void>) {
  const statuses: SaveStatus[] = [];
  const s = createAutosaver({ save, delay: 800, onStatus: (x) => statuses.push(x) });
  return { s, statuses };
}

it("debounces rapid updates into one save of the latest value", async () => {
  const save = vi.fn().mockResolvedValue(undefined);
  const { s, statuses } = setup(save);
  s.update("a"); s.update("ab"); s.update("abc");
  expect(statuses[0]).toBe("pending");
  await vi.advanceTimersByTimeAsync(799);
  expect(save).not.toHaveBeenCalled();
  await vi.advanceTimersByTimeAsync(1);
  expect(save).toHaveBeenCalledExactlyOnceWith("abc");
  expect(statuses.at(-1)).toBe("saved");
});

it("never overlaps saves and saves the newest value after the in-flight one", async () => {
  let release!: () => void;
  const save = vi.fn()
    .mockReturnValueOnce(new Promise<void>((r) => (release = r)))
    .mockResolvedValue(undefined);
  const { s, statuses } = setup(save);
  s.update("v1"); await vi.advanceTimersByTimeAsync(800);
  s.update("v2"); await vi.advanceTimersByTimeAsync(800);
  expect(save).toHaveBeenCalledTimes(1);
  release(); await vi.runAllTimersAsync();
  expect(save).toHaveBeenCalledTimes(2);
  expect(save).toHaveBeenLastCalledWith("v2");
  expect(statuses.filter((x) => x === "saved")).toHaveLength(1);
  expect(statuses.at(-1)).toBe("saved");
});

it("reports error on failure and retries on the next update", async () => {
  const save = vi.fn().mockRejectedValueOnce(new Error("offline")).mockResolvedValue(undefined);
  const { s, statuses } = setup(save);
  s.update("x"); await vi.advanceTimersByTimeAsync(800);
  expect(statuses.at(-1)).toBe("error");
  s.update("xy"); await vi.advanceTimersByTimeAsync(800);
  expect(save).toHaveBeenLastCalledWith("xy");
  expect(statuses.at(-1)).toBe("saved");
});

it("flush saves a pending value immediately", async () => {
  const save = vi.fn().mockResolvedValue(undefined);
  const { s, statuses } = setup(save);
  s.update("draft");
  await s.flush();
  expect(save).toHaveBeenCalledExactlyOnceWith("draft");
  expect(statuses.at(-1)).toBe("saved");
});

it("flush with nothing pending does not save", async () => {
  const save = vi.fn().mockResolvedValue(undefined);
  const { s } = setup(save);
  await s.flush();
  expect(save).not.toHaveBeenCalled();
});
```
